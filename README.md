# Undercurrent

**Слышим то, что не говорят вслух**

Анонимный ИИ-собеседник для сотрудников и агрегированная HR-аналитика риска
выгорания. Казахстан.

Два продукта в одном коде:

- **B2B** — компания подключает сотрудников и платит за обезличенные тренды по
  отделам. Фиксированная цена за размер команды, не за человека.
- **B2C** — личная подписка сотрудника, не зависящая от работодателя.

---

## Главное, что отличает продукт от опроса вовлечённости

Работодатель **не может** прочитать переписку. Не «не имеет права», не «мы
обещаем не смотреть» — а не может, потому что связи между человеком и его
разговорами не существует в базе данных.

Схема разрезана надвое:

```
   ЛЕВАЯ ПОЛОВИНА                    ПРАВАЯ ПОЛОВИНА
   право на вход                     что человек написал

   employee_access                   conversations
   corporate_email_hash              anonymous_session_id
   access_grants                     messages, mood_entries
        │                                   │
        └────────── company_id ─────────────┘
                 «сотрудник этой компании»
                  а не «вот этот сотрудник»
```

Между половинами нет ни одного внешнего ключа. Соединяет их только
`company_id` — то есть факт принадлежности к компании, а не личность.

Это обеспечивается двумя разными учётными записями. Сотрудник подтверждает
корпоративную почту, получает одноразовый код, **выходит из аккаунта** и
входит заново анонимно. Код гасится при использовании. Через границу
переносится ровно один факт: «предъявитель работает в компании X».

Подробности — в [`AGENTS.md`](AGENTS.md) и в комментариях
[`supabase/migrations/`](supabase/migrations/).

### Порог анонимности

Срез по отделу не показывается, пока в нём не наберётся достаточно разных
собеседников (по умолчанию 5). В отделе из двух человек «риск вырос до 80» —
это сообщение о конкретном человеке, как его ни называй.

Порог применяется политикой в базе, а не фильтром в интерфейсе: строки ниже
порога до HR физически не доезжают.

## Стек

| Слой | Технология |
|---|---|
| Клиент | Expo (React Native + TypeScript), веб и мобильные из одного кода |
| Бэкенд | Supabase — Postgres, Auth, RLS |
| ИИ-слой | Курируемая база одобренных формулировок (`src/lib/companion.ts`) |

ИИ-слой намеренно не свободная генерация: ответ, который увидит человек в
плохом состоянии, должен утверждать специалист, а не выбирать модель по
правдоподобию. Сейчас база лежит в коде; подключение RAG меняет реализацию
одной функции, но не её место в системе.

## Запуск

```bash
npm install
cp .env.example .env    # подставить URL и anon-ключ проекта Supabase
npm run web
```

Схема разворачивается вставкой файлов из `supabase/migrations/` по порядку в
SQL Editor. Демо-данные для дашборда — `supabase/seed.sql`.

Настройки проекта Supabase, без которых вход не работает:

- **Anonymous Sign-Ins** — включить
- **Site URL** и **Redirect URLs** — адрес, куда возвращает письмо

## Проверки

```bash
npm test
```

Три уровня, каждый запускается и отдельно:

| Команда | Что проверяет |
|---|---|
| `npm run typecheck` | типы |
| `npm run test:crisis` | распознавание кризисных сигналов и маркеров |
| `npm run test:db` | миграции и изоляцию на настоящем Postgres в Docker |
| `npm run verify:prod` | весь путь сотрудника на боевом проекте Supabase |

`verify:prod` стоит особняком: он идёт против настоящего проекта, а не
против контейнера, и проверяет то, чего в схеме нет — включён ли
анонимный вход, развёрнута ли функция `companion`, ведут ли себя
политики так же, как локально. Схема может быть безупречной, а продукт
не работать, потому что забыли нажать «Save changes» в дашборде.

Требует `.env.secret` со служебным ключом, поэтому запускается вручную.
За собой убирает — созданные учётные записи удаляются.

`test:db` поднимает чистый `postgres:16`, применяет миграции и прогоняет
сценарии: путь сотрудника от почты до анонимного чата, попытки HR добраться до
переписки, работу порога выборки. Тест
[`db-tests/30_isolation.sql`](db-tests/30_isolation.sql) проверяет отсутствие
связей между половинами схемы структурно — запросом к системному каталогу, а
не доверием к коду.

## Безопасность и границы

- Переписка не покидает базу; в агрегаты уходят только обезличенные оценки
  без цитат, имён и должностей
- Корпоративная почта хранится хэшем
- Время выдачи билета огрублено до даты — точное время входа сузило бы круг
  подозреваемых
- Сообщения о желании уйти из жизни обрывают обычный сценарий и выводят
  контакты кризисных служб (`src/lib/companion.ts`)

**Чего в продукте нет и не будет:** способа для HR прочитать переписку,
выгрузки сообщений, идентификации сотрудника по разговору. Это не вопрос
тарифа.
