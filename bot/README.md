# Телеграм-бот Undercurrent

Полноценный клиент для личной подписки: разговор, дневник, выгрузка,
удаление. Плюс уведомления для HR и вход в приложение для сотрудника.

## Ограничение, из которого следует вся конструкция

**Telegram знает, кто человек.** За чатом стоит номер телефона,
проверенный при регистрации. Бот обязан помнить собеседника, иначе не
сможет продолжить разговор — значит связка «чат ↔ данные» существует по
определению.

Вопрос только в том, к каким данным она ведёт. Здесь — только к именным
учётным записям:

| Кто | Что получает от бота | Анонимность |
|---|---|---|
| **HR** | Уведомления об изменениях по отделам | Не затрагивается: аккаунт именной, данные обезличены |
| **B2C** | Напоминания про дневник | Не нарушается: подписка и так именная |
| **Сотрудник B2B** | Ссылку в приложение | Сохраняется: переписки в Telegram нет |

Связать чат с анонимной сессией сотрудника нельзя. Запрет живёт не в
боте, а в триггере `telegram_link_guard` внутри Postgres — бот ходит
служебным ключом, мимо всех политик, и остановить его может только
правило в самой базе. Появится второй бот или служебный скрипт — правило
продолжит работать без их участия.

Проверяется в [`db-tests/50_telegram.sql`](../db-tests/50_telegram.sql),
в том числе попытка привязки служебным ключом напрямую.

## Запуск

```bash
cd bot
python -m venv .venv
.venv\Scripts\activate        # Windows;  source .venv/bin/activate — Linux/macOS
pip install -r requirements.txt
copy .env.example .env         # вписать токен от @BotFather
python bot.py
```

Нужны три значения из трёх разных файлов — каждое лежит ровно в одном
месте, дублей нет:

| Файл | Что в нём | В репозитории |
|---|---|---|
| `bot/.env` | токен Telegram, адрес приложения | нет |
| `.env` (корень) | адрес проекта Supabase | нет |
| `.env.secret` (корень) | секретный ключ Supabase | нет |

## Зачем боту секретный ключ

Он читает коды привязки и отмечает доставленные уведомления — обе
операции закрыты для обычного пользователя намеренно. Ключ обходит RLS,
поэтому бот запускается на машине, которую вы контролируете, а не на
бесплатном хостинге.

Чего ключ **не** отменяет: страж в базе. Даже с ним нельзя связать чат с
анонимной сессией.

## Как привязывается человек

1. В приложении: **Настройки → Подключить Telegram → Получить ссылку**
2. Ссылка вида `t.me/UndercurrentBot?start=<код>` — одно нажатие
3. Бот гасит код и создаёт привязку

Код одноразовый и живёт пятнадцать минут. Тот же приём, что с билетами
доступа, и по той же причине: код, оставшийся в базе, однажды окажется
в чужой переписке.

## Уведомления

Строки создаёт база (`notify_hr_on_risk`), бот разносит. Приложение и
Telegram — два окна в одни данные.

Порядок «отправить → отметить» выбран сознательно: при падении между
шагами человек получит уведомление дважды — заметно и безобидно.
Обратный порядок терял бы его молча, а молча потерянное уведомление о
росте риска означает, что HR не узнал вовремя.

Строки для непривязанных пропускаются **без отметки** и приходят пачкой
сразу после привязки. Это следствие ограничения Telegram: бот не может
написать первым тому, кто сам не начинал диалог.

Уведомления подчиняются порогу анонимности так же, как дашборд. Без
этого порог оказался бы декоративным: срез, скрытый на экране, приезжал
бы в телефон открытым текстом.

## Что умеет

| Команда | Что делает |
|---|---|
| `/login` | заводит личную подписку на этот Telegram — без почты и пароля |
| `/mood` | отметка состояния кнопками; шкала с подписями, а не цифрами |
| `/export` | всё, что о вас хранится, файлом |
| `/delete` | удаляет историю; доступ при этом сохраняется |
| `/unlink` | отвязывает чат |

Про `/export` файлом, а не сообщением: переписка за месяц не помещается
в лимит Telegram, а обрезанная выгрузка хуже отсутствующей — человек
решит, что это всё, что о нём хранится.

Про `/mood` без заметки: спросить её следующим сообщением значило бы
перехватить реплику, адресованную собеседнику. Заметки остаются в
приложении.

## Чего бот не делает

**Не содержит ни одного правила беседы.** Разговор бот ведёт, но текст
уходит в Edge Function `companion`, которая исполняет тот же
[`src/lib/companion.ts`](../src/lib/companion.ts), что и приложение.
Не копию — тот же файл: Deno исполняет TypeScript напрямую.

Переписать эти правила на Python значило бы завести вторую копию,
которая разойдётся с первой молча. Цена расхождения не абстрактная:
приложение распознало бы сообщение о желании уйти из жизни, а бот
ответил бы вопросом про нагрузку.

Признак кризиса и телефоны доверия функция возвращает вместе с ответом —
чтобы боту не пришлось решать самому, кризис это или нет. Решение
принимается там же, где и для приложения.

**Не двигает бизнес-логику в себя.** Служебный ключ не имеет
`auth.uid()`, на который опираются все политики. Обёртка с аргументом
`user_id` соблазнительна и ровно так правила и разъезжаются.

Там, где бот всё же пишет в базу напрямую — дневник, удаление истории, —
он опирается на инвариант, который держит сама база: привязка чата
возможна только к именной сессии, и это проверяет триггер. Бот не решает,
кому можно; он читает, кому уже можно.
